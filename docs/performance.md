# 応答性の改善と検証（2026-10-23）

Tauri / SolidJS / Rust を維持し、既存の作業ツリーを基準に変更した。

## 計測結果

Windows、Node.js v24.19.0。フロントエンドは10,000件の合成ファイル情報を使用。
同じスクリプトでウォームアップ3回、計測15回の中央値を比較した。

| 処理 | 改善前 | 改善後 |
| --- | ---: | ---: |
| 選択反転 | 9,209.185 ms | 6.250 ms |
| タブ切替時の状態処理 | 229.781 ms | 0.01 ms 未満 |
| フォルダ移動時のフロントエンド処理 | 18.118 ms | 19.306 ms |
| 一覧更新時のフロントエンド処理 | 17.162 ms | 20.965 ms |

タブの改善前は左右の状態をJSONで保存・復元する従来の処理、改善後は2タブ間を
往復する状態切替を測定した。DOMの更新、描画、IPC、実ファイルの読み出しは含まない。
選択反転は全選択と未選択を交互に切り替える。ホスト上の他プロセスの負荷は固定していない。
数値はこの環境での参考値であり、実画面の描画時間や一定の高速化率を保証するものではない。

Rustの実ファイル計測は10,000件の小さなファイル、debugビルド、一覧は初回を除く5回の
中央値。一覧取得は202.566 → 201.888 ms、コピーは5,527.786 → 6,260.941 msだった。
コピーの転送速度改善は確認していない。今回の主目的は、その処理中に画面を止めないこと。

## 実装

- ローカルの一覧取得、コピー、移動、削除、作成、リネーム、テキスト読み出し、
  ドライブ取得などは `background::run` 経由でblockingワーカーに移した。
- SFTP転送内のローカルI/Oは `tokio::fs` を使い、非同期ワーカー上の同期I/Oを除いた。
- タブごとにペインを保持する。切替時のJSON複製を廃止し、進行中の読み込みも元のペインに帰属する。
- 選択反転と描画時の選択判定をSetで処理する。親ディレクトリ `..` は選択対象から除く。
- 並び替えは表示設定を持つフロントエンドで1回行う。比較キーは事前に作成する。
- 更新時のカーソルと選択はファイル名で復元する。古い非同期応答・エラーは現在の一覧を上書きしない。
- コピー・移動・削除に処理済み項目数、経過時間、停止要求を追加。失敗・停止後も影響した場所の一覧を更新する。
- 確認ダイアログで消費したEnter/Escapeが一覧へ伝わる問題を修正。
- 終了操作に必要な `core:window:allow-close` をmainウィンドウに許可。

停止は選択した項目の間で行う。1つのフォルダとその配下は1項目として扱い、処理途中の
ファイルやフォルダを強制中断しない。完了した項目は元に戻さない。
SFTPの移動ではコピー段階で停止した場合、元ファイルを削除しない。
全コピー後の元ファイル削除段階は途中停止しない。進捗の件数はコピー段階の項目数であり、バイト数ではない。

## 検証

- `npm run check` と `npm run build`
- `npm test`：非同期応答の競合、エラー、選択維持、履歴、タブの独立性と切替・終了・左右入替
- `cargo check --manifest-path src-tauri/Cargo.toml --offline --locked`
- `cargo test --manifest-path src-tauri/Cargo.toml --offline --locked --lib`：ワーカー実行、停止境界、途中失敗、実ファイルのコピー・移動・リネームと衝突
- Windows debug版を起動し、専用の6フォルダ・18,000ファイルでコピー完了、処理中のペイン切替、
  進捗表示、項目間での停止と結果表示を確認。停止後も元の18,000ファイルの内容が一致。
  タブの追加と切替、確認ダイアログのEnterで現在地が変わらないことも確認。

SFTP実サーバーとの接続と転送、およびmacOS/Linuxの実画面は未検証。
CIでは3 OSで型チェック、ビルド、回帰テストを実行する構成にしたが、リモートCIはこの作業では起動していない。

## 再計測

```sh
npm run bench
cargo test --manifest-path src-tauri/Cargo.toml benchmark_local_filesystem -- --ignored --nocapture
```

Rustのベンチマークは一意な一時ディレクトリに検証ファイルを作成し、そのディレクトリだけを片付ける。
通常のテスト実行では重いベンチマークをスキップする。

Windowsの実画面を検証するときは、debugビルド限定の環境変数 `KUF_DEV_CONFIG_DIR` で
検証専用の設定ディレクトリを指定できる。releaseビルドではこの変数を参照しない。
今回使った設定・ファイルは `.test-run/native/` 配下に隔離し、検証後に削除した。
検証用アプリと開発サーバーも終了している。`.test-run/` はGitの対象外。
