# 操作性の改善と検証（2026-10-23）

## v0.4.0の追加操作

あふｗ・だいなファイラーを参考にした選択、履歴、左右比較、一括リネーム、配下検索、ZIP、外部コマンドとプレビューは、[比較・操作ガイド](filer-comparison.md)にまとめています。Ctrl+Shift+Pから操作名で検索して実行できます。

Tauri / SolidJS / Rustを維持し、次の4機能を追加した。

## ソート

- 「表示 → 並び順（ソート）...」、各ペインのパス横の「名前 ↑」などのボタン、または `Ctrl+Shift+S` で変更する。
- 名前・拡張子・サイズ・更新日時と、昇順／降順を選べる。変更するのは操作中のペインだけ。`Ctrl+Shift+R` で昇順／降順を反転する。
- キーマップの「表示」に、ソート選択・各項目への直接切替・昇降順の反転を用意した。既存のカスタム割り当てを優先する。
- 並べ替えでフォルダーを読み直さず、カーソルと選択を同じ名前の項目に保つ。更新やフォルダー移動後もそのペインの順序を使う。
- 親フォルダー `..` は常に先頭。「フォルダーを先に表示」は降順でも維持する。更新日時は取得した実時刻で比較し、不明なものは最後に置く。
- あいまい絞り込み中は一致度を優先し、同じ一致度の項目を指定した順で並べる。部分一致・ワイルドカードでは指定した順で並べる。
- 左右それぞれの順序を、前回の状態・名前付き作業セットにも保存する。古い作業セットは名前の昇順で開ける。新しいタブは元のタブの並び順を引き継ぐ。

## 即時絞り込み

- `/`、`Ctrl+F`、または「表示 → 一覧を絞り込む」で、操作中のペインに入力欄を開く。
- 通常は「あいまい」で検索する。`usrctrl` → `UserController.ts` のように文字を飛ばした一致にも対応し、完全一致・先頭一致・連続した一致を優先して並べる。一致した箇所をファイル名と拡張子で強調する。
- 空白区切りはAND条件。`report pdf` は順序に関係なく両方に当たる名前を探す。全角・半角、英字の大文字・小文字、ひらがな・カタカナの違いも吸収する。
- Migemo辞書を同梱し、`nihon` → 日本、`siryou` → 資料、`shiyou` → 仕様を検索できる。2文字以上のローマ字が対象。初回の絞り込みで辞書を読み込み、オフラインで利用できる。辞書準備中や読み込み失敗時も通常の曖昧検索は使える。
- 「あいまい / 部分一致」ボタンで切り替えると、空白を含めた連続部分一致にも戻せる。`*.txt`、`report-?.csv` のような `*`・`?` を含む条件は、どちらのモードでも名前全体へのワイルドカードとして扱う。入力は128文字まで。
- `Enter`・`↓` で絞り込みを残して一覧操作へ戻る。入力欄の `Esc`、一覧の `Esc`、または `×` で解除する。
- コピー・移動・削除・全選択は、表示された項目を対象にする。親フォルダの `..` は絞り込み中も残し、選択対象から除く。
- 条件はペインごとに保持し、自動更新でも維持する。別の場所へ移動すると解除する。
- 対象は表示中のフォルダー内。入力条件を変えたときは最上位の候補を選び、自動更新時は同名項目のカーソルと選択を維持する。

Migemoには [jsmigemo](https://github.com/oguna/jsmigemo) を使用する。辞書・ライセンスと出典は `public/migemo/NOTICE.md` に記載。検索条件やファイル名を外部サービスへ送らず、同梱辞書だけで処理する。

## 作業セットの保存・復元

- 「作業セット → 現在の構成を保存...」で名前を付けて保存する。同名を保存する場合は上書きを確認する。
- 「作業セット → 保存した作業セット...」で一覧を開き、`↑`・`↓` で選んで `Enter` または「復元」。ダブルクリックでも復元できる。`Esc` で閉じる。
- 「削除」は確認後に登録だけを削除し、フォルダやファイルには触れない。
- 前回の構成も自動保存する。起動時の復元は、設定の「起動時に前回の左右の場所とタブを復元する」で切り替える。復元しない場合は設定した起動フォルダを開く。

保存先は設定ディレクトリの `workspaces.json`。保存内容は、各タブの左右のパスと並び順、操作中の左右ペイン、アクティブなタブ、および作業セット名。ファイル一覧、カーソル位置、選択、移動履歴、絞り込み条件、パスワードや秘密鍵は保存しない。上限は1構成64タブ、名前80文字、保存ファイル16 MiB。

復元後の一覧はアクティブなタブから読み込み、他のタブは切替時に読み込む。存在しない場所や未接続のSFTPもパスを保持し、エラーを表示する。接続・場所を確認して `Ctrl+R` で再試行できる。SFTPへの自動接続は行わない。

保存処理は直列に実行し、一時ファイルへの書き込み後に置き換える。壊れたJSON、未対応のバージョン、不正な構成は上書きしない。起動時に保存内容を読み込めなかった場合は既存の状態を保全し、名前付き保存の前にも既存データを再確認する。終了時に保存できなければ、保存せず終了するか確認する。

## 一覧の自動更新

- 表示中のローカル2ペインを監視し、外部アプリによる作成・更新・削除などを反映する。タブ切替時とアプリへ戻ったときにも一覧を更新する。
- 連続した通知はまとめる。ファイル処理中、起動・作業セット復元中、ペインの読み込み中は更新を保留し、処理後に反映する。
- 残っている同名項目のカーソルと選択、絞り込み条件を維持する。古い非同期応答で移動先を巻き戻さない。
- 監視に失敗した場合は表示して再試行する。手動の `Ctrl+R` も引き続き使える。非表示タブとSFTPは常時監視の対象外。

ネットワーク共有の変更通知はOSと共有先に依存する。通知が届かない場合は、アプリへ戻ったときの更新または手動更新を使う。

## ごみ箱対応

- ローカルで `Delete`・`F8` などの削除操作を行うと、確認後にOSのごみ箱へ移動する。復元はOSのごみ箱から行う。
- Windowsはローカルの固定ドライブだけに対応する。ネットワーク、リムーバブルドライブ、安全に扱えないパス、ごみ箱へ移動できない対象はエラーで停止し、完全削除へ切り替えない。
- SFTPはごみ箱に対応しない。「リモートを完全削除」の確認後に永久削除し、復元できないことを明示する。
- 複数項目の途中で失敗・停止した場合、完了した移動を自動で戻すことはしない。移動処理に伴う元ファイルの片付けは、通常の削除操作とは別の処理。

## 検証

- フロントエンドの回帰試験27件成功。曖昧一致の順位・空白AND・正規化・元文字への強調位置・部分一致モード・実辞書のMigemoを含む。絞り込みの操作対象、選択維持、作業セットの保存形式・独立性、タブ数が減る復元、自動更新の通知集約と処理中保留、Windows同一パスの別表記とUnixの大文字小文字の区別も確認した。
- WindowsのRust通常試験41件成功、3件は通常実行ではスキップ。既存設定とキーバインドの保全、作業セットの破損保持・置換失敗時の原本保全、監視、削除対象の事前検証、同一ファイルとハードリンクへのコピー・移動の拒否、SFTP転送の型衝突とスキップ時の移動中止、ターミナル起動の引数構築を確認。Unix向けにはシンボリックリンク経由の監視・置換を確認する追加試験をCIで実行する。
- スキップ対象のうちWindowsごみ箱の2件は別途明示実行し、両方成功。新規生成したファイル・空フォルダ・階層付きフォルダを移動し、返されたごみ箱項目を使って正確に復元して内容を照合した。排他ロックで移動できない場合にも元の内容が残ることを確認した。残る1件は既存の大量ファイル用ベンチマーク。
- Windowsのネイティブ画面で、起動時の2タブ復元、`*.txt` の即時絞り込み、外部での `gamma.txt` 作成と `alpha` への追記の反映、更新後の絞り込み維持、名前付き2タブ保存、1タブ構成への復元を確認。
- 正常終了後に再起動し、左右の場所・タブ構成・操作中の右ペインの復元を確認。`Ctrl+F` からの入力と一致0件表示も確認した。
- 起動時に試験用JSONを読み込めない状態にし、起動後に有効な元データを戻してから終了。元データのSHA256が変わらず、起動時の代替構成で上書きされないことを確認した。
- `npm run check`、`npm run build`、Windows debugビルド成功。

通常試験:

```sh
npm test
cargo test --manifest-path src-tauri/Cargo.toml --offline --locked --lib
```

Windowsごみ箱の明示試験（検証専用の生成データだけを対象にする）:

```sh
cargo test --manifest-path src-tauri/Cargo.toml --offline --locked --lib windows_recycle_and_restore_generated_items -- --ignored --nocapture
cargo test --manifest-path src-tauri/Cargo.toml --offline --locked --lib windows_recycle_failure_preserves_generated_item -- --ignored --nocapture
```

SFTP実接続とmacOS/Linuxの実画面、ごみ箱容量超過・OS設定でごみ箱を無効にした場合は未検証。試験用の設定・ファイルは実際のユーザー設定から分離し、検証後に生成データを照合して削除した。検証用アプリは終了し、通常の開発版アプリは利用できる状態で起動している。

### 曖昧検索・Migemoの追加確認

Windows実画面で `nihon` →「日本語ガイド」、`usrctrl` →「UserController」、`siryou pdf` →「打ち合わせ資料.pdf」を確認した。部分一致に切り替えるとローマ字だけでは日本語名に当たらず、戻すと再び一致する。日本語名・英字の飛び飛びの文字・分離された拡張子の強調表示も確認した。

`node scripts/benchmark-filter.mjs` は1万件の英字・日本語混在名で、照合、順位付け、強調位置とSolidの状態更新を測定する。Node 24.19.0、15回の中央値は `usrctrl` 19.1ms、`siryou pdf` 10.3ms、`nihon` 8.3ms、`*.txt` 12.4ms。初回の名前準備を含む検索は146.8ms、辞書初期化は9.8msだった。ファイルI/O、IPC、実画面の描画時間は含まない。名前の正規化結果は一覧ごとに再利用する。
